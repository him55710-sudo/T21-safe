# 의사에게 도움이 되는가 — 진단 한 장

**문서 상태:** 창업자 검토용 · 2026-09-07 (KST)
**성격:** FACT / INTERPRETATION / DECISION / EXTERNAL_DEPENDENCY
**범위:** 연구용 · 관찰 전용 · 임상 검증 아님 (`clinical_validation=false`)

> 이 문서는 진료 제품을 승인하지 않습니다. 성능·시장·매출 수치를 만들지 않습니다.

## 1. 한 줄 결론

**INTERPRETATION.** 지금 형태는 **연구 인프라 후보**이지, 의사가 내일 수술실에서 쓰는 **제품이 아니다.**
쓸모가 없다기보다, **의사가 실제로 막히는 지점**과 **우리가 쌓아 온 결과물**이 아직 안 맞는다.

## 2. 의사가 DS 마취에서 실제로 신경 쓰는 것

**FACT (공개 임상 교육·리뷰에서 반복되는 우선순위).**

1. **수술 전:** 선천성 심장병·폐고혈압 심초음파, OSA·상기도감염, 이전 마취기록, 경추 증상 확인
2. **기도:** 튜브 한 사이즈 작게, 마스크 환기 어려움 대비, 목 중립 유지, 비디오 후두경 고려
3. **유도:** sevoflurane 유도 시 서맥이 더 흔하고 심할 수 있음 → 항콜린제 준비 (이미 ‘알려진 임상 사실’에 가깝다)
4. **수술 후:** 기도 폐쇄·OSA로 관찰 연장

합의가 부족한 쪽은 대개 **경추 검사 범위, 기도 기구 선택, 진통제 용량** 같은 **프로토콜·사람 판단**이다.
문헌에서 “실시간 위험 점수 하나”가 1순위 니즈로 나오는 경우는 드물다.

**EXTERNAL_DEPENDENCY.** 우리 병원·우리 PI의 우선순위는 면담으로만 확정된다. 위 목록은 일반 공개 자료 기준이다.

## 3. 우리가 지금 가진 것과의 괴리

**FACT.** 공개·합성 자료로 신호 품질, 시간축 정렬, 연구용 점수·화면을 다듬어 왔다. 재현 가능한 **연구 파이프라인**으로는 의미가 있다.

**INTERPRETATION.** 의사·병원의 하루를 바꾸려면 보통 아래가 먼저다.

| 의사가/병원이 자주 묻는 것 | 지금 제품 스토리가 강조하기 쉬운 것 |
| --- | --- |
| 우리 병원에 DS 사례·신호가 얼마나 있나 | 실시간 점수와 색상 구간 |
| 장비·시계·항목을 맞출 수 있나 | 공개 데이터에서의 심박 사건 정리 |
| 연구용으로 쓸 수 있는/없는 구간은? | “위험도”처럼 읽히기 쉬운 한 숫자 |
| 조용히 기록·비교하는 관찰 연구 | 데모에서 눈에 띄는 라이브 화면 |

괴리를 줄이려면 스토리를 **예측 AI**에서 **공동연구의 자료 준비도**로 옮겨야 한다.
이미 [병원 공동연구 PoC 제안서](../business/HOSPITAL_POC_PROPOSAL_KR.md)와 [근거 우선 전환 결정](T21_REFOCUS_DECISION_KR.md)이 그 방향이다.

## 4. CDS·알람 피로 함정

**FACT.** 중환자·마취 영역의 임상결정지원(CDS) 문헌에서는 예측 도구 사용률이 낮고, 과다 알림·업무 흐름 불일치·설명 부족이 반복 실패 원인으로 나온다.
우리 [임상 워크플로 감사](../product/CLINICAL_WORKFLOW_AUDIT.md)도 **한 숫자가 시선을 훔칠 위험**, WATCH/ELEVATED/HIGH가 경보처럼 읽힐 위험을 이미 적었다.

**INTERPRETATION.** 기능이 늘수록 “의사에게 도움”처럼 보이기 쉽지만, **검증 전 점수 UX는 신뢰를 깎을 수 있다.** 그래서 기능 확장보다 이해도 연구·표현 절제가 먼저다.

## 5. 권고 방향

### A. 단기 — 의사·병원에 바로 말 되는 가치

**DECISION (권고).** “예측 AI”가 아니라 **DS 마취 공동연구의 자료 준비도**로 판다.

1. 집계 가능 여부 ([집계 질의서](../business/HOSPITAL_AGGREGATE_FEASIBILITY_QUERY_KR.md))
2. 스키마·시계 시험 ([시험 기준](../research/SCHEMA_CLOCK_PILOT_ACCEPTANCE.md))
3. 승인 후 최소 추출만 별도 제안

**산출물 예시:** 비식별 파이프라인, 신호품질 리포트, 연구용 재생.
**점수는 숨기거나 넣지 않는 옵션을 기본으로 둔다.**

### B. 중기 — 논문급 질문

**DECISION (권고).** 연구 질문을 “점수가 불안정을 예측한다”에서 빼고, PI와 함께 서술·재현성 질문으로 좁힌다. 예:

- 유도기 서맥의 **시점·맥락·회복**을 후향적으로 얼마나 재현성 있게 기술할 수 있는가
- **사건 정의·판정 일치도**를 먼저 잡을 수 있는가 (예측보다 라벨이 먼저)

상세 선택지는 [임상 연구 잠금](../research/CLINICAL_RESEARCH_LOCK_V0.md)과 [PI 의사결정 팩](PI_DECISION_PACK_KR.md)에 둔다.
면담용 니즈 질문은 [PI 면담용 질문](PI_CLINICIAN_NEEDS_QUESTIONS_KR.md)을 쓴다.

### C. 하지 말 것

- 임상 잠금 전 점수·임계값 튜닝, 공개데이터 벤치 확장으로 “임상처럼” 보이게 만들기
- 알람처럼 보이는 UX 강화
- “의사에게 도움 되는 제품”으로 마케팅
- 기도·경추처럼 **사람 프로토콜이 핵심인 영역**을 소프트웨어가 대체한다는 약속

## 6. Evidence-First와의 정합성

**FACT.** 기능 확장 동결·근거 문서·병원 PoC 문안은 이미 이 진단과 같은 방향을 가리킨다.

**INTERPRETATION.** 다음 병목은 Codex로 기능을 더 쌓는 일이 아니라 **연구책임자와의 대화**다.
에이전트는 병원·PI 메일을 보내지 않는다. 연락은 창업자가 직접 한다.
