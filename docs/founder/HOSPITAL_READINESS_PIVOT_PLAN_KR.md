## 2. 성공 / 실패 정의

### 성공 (이 피벗의 Done)

1. 창업자가 병원에 들고 갈 **PoC 한 묶음**(제안서 + 집계 질의 + 시험 기준)이 최신 상태로 정리됨
2. **1곳 이상**과 집계 질의 발송·회신 또는 “거절/보류”가 **문서에 기록**됨 (결과는 성공·실패 모두 진전)
3. 회신이 있으면 **집계 판정 메모**를 남김 (합격 숫자를 새로 만들지 않음)
4. 기관이 허용하면 **1–3건 스키마·시계 시험**까지 진행하고 엔지니어링 PASS/HOLD만 기록
5. 이 과정에서 **점수 튜닝·기능 확장·임상 성능 주장**이 없음

### 실패 신호 (즉시 멈춤)

- 예측·경보·투약·시술 가능 여부를 약속함
- 환자별 식별자료·파형 원본을 채팅·Notion·공개 저장소에 올림
- 집계 전에 대규모 추출을 요청함
- 공개·합성 데모 결과를 “우리 병원 DS 성능”처럼 말함
- 에이전트가 병원·PI에 연락함

## 3. 3단계 실행 (본체)

### 단계 0 — 창업자 준비 (지금 · 0–7일)

| # | 할 일 | 산출물 | 담당 |
| --- | --- | --- | --- |
| 0.1 | PoC 문안·금지 문장 최종 읽기 | 체크된 [PoC 제안서](../business/HOSPITAL_POC_PROPOSAL_KR.md), [데모 안내](DEMO_GUIDE_KR.md) | 창업자 |
| 0.2 | 집계 질의표에서 기관에 맞게 **빈칸만** 표시 (범주 숫자 발명 금지) | 발송용 질의 초안 | 창업자 (+문서 지원은 에이전트) |
| 0.3 | 대상 기관 1–2곳과 내부 연락 창구 정하기 | 창업자 메모(비공개) | 창업자만 |
| 0.4 | PR #19(의사 니즈 진단·PI 질문) 머지 | main에 진단 문서 | 창업자(GitHub 승인) |

**단계 0 완료 조건:** 발송 가능한 질의 초안 + PoC 제안서 + “에이전트는 메일 안 함” 재확인.

### 단계 1 — 집계 확인 (핵심 · 1–4주)

| # | 할 일 | 산출물 | 담당 |
| --- | --- | --- | --- |
| 1.1 | 집계 질의 **수동** 발송 | 발송일·수신자 기록(창업자) | 창업자 |
| 1.2 | 회신 수령 · PHI/환자행 없는지 1차 확인 | 집계표만 보관 | 창업자 |
| 1.3 | 판정 메모: 충분/부족/보류 + 다음 질문 | `feasibility` 메모(비식별) | 창업자 · 필요 시 PI |
| 1.4 | (선택) 같은 질의로 백업 기관 | 동일 형식 기록 | 창업자 |

**단계 1 완료 조건:** 최소 1건의 발송 결과가 기록됨. 대규모 추출 없음.

**에이전트 역할:** 회신 요약 초안·판정 표 정리만. 회신 원본에 식별정보가 보이면 **열람 중단을 창업자에게 알리고** 저장하지 않음.

### 단계 2 — 스키마·시계 소규모 시험 (조건부 · 2–6주)

진입 조건: 단계 1에서 “다음으로 구조 시험 가능” + 기관 승인(IRB/DUA/보안) + 창업자 서면 go.

| # | 할 일 | 산출물 | 담당 |
| --- | --- | --- | --- |
| 2.1 | 합성 또는 허용된 1–3건 비식별 샘플 수령 | 전달 경로·보존 기한 기록 | 창업자 · 기관 |
| 2.2 | [스키마·시계 시험 기준](../research/SCHEMA_CLOCK_PILOT_ACCEPTANCE.md)으로 점검 | PASS / HOLD / 재요청 | 기술 담당 · 창업자 확인 |
| 2.3 | 점수·임계값 **변경하지 않음** | 변경 없음 확인 | 전원 |
| 2.4 | PI에게 “이 자료로 어떤 서술 질문이 가능한지”만 물음 | 면담 메모([PI 질문지](PI_CLINICIAN_NEEDS_QUESTIONS_KR.md)) | 창업자 |

**단계 2 완료 조건:** 엔지니어링 PASS 또는 HOLD가 문서화됨. PASS ≠ 임상 검증 ≠ 전체 추출 승인.

### 단계 3 — 최소 추출 제안만 (별도 게이트)

단계 2 PASS + PI가 연구 질문 초안을 좁힘 + 기관 승인 후에만 **별도 문서**로 최소 추출을 제안한다.
이 실행 계획의 기본 Done은 단계 1–2까지다. 단계 3은 새 승인 패키지.

## 4. 하지 않는 일 (피벗 기간)

- 엔진 점수·임계값·가중치 튜닝
- 공개데이터 벤치 확장으로 임상처럼 보이게 하기
- MCP·기능 확장, freeze tip 연속 발행
- 알람형 UX 강화
- 병원·PI 자동 메일
- Notion/Grok에 PHI·파형·자격증명 저장

기능 개발 재개(unfreeze)는 **창업자 서면** + 이 피벗의 단계 1–2 기록 이후에만 검토한다.
